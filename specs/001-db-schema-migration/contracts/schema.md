# Contract: Resulting PostgreSQL Schema

This feature has no HTTP/API surface of its own — its "contract" is the schema that `packages/api/migrations/` produces and that all later repository/service code (and the Mermaid diagram) must stay consistent with. This file is the authoritative DDL shape; `data-model.md` explains the *why* behind it.

```sql
-- categories
CREATE TABLE categories (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name        TEXT NOT NULL UNIQUE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- tags
CREATE TABLE tags (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name        TEXT NOT NULL UNIQUE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- pets
CREATE TABLE pets (
  id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name         TEXT NOT NULL,
  category_id  BIGINT REFERENCES categories(id) ON DELETE SET NULL,
  status       VARCHAR(16) NOT NULL CHECK (status IN ('available', 'pending', 'sold')),
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- pet_photo_urls
CREATE TABLE pet_photo_urls (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  pet_id      BIGINT NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  url         TEXT NOT NULL,
  "position"  INTEGER NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (pet_id, "position")
);

-- pet_tags
CREATE TABLE pet_tags (
  pet_id      BIGINT NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  tag_id      BIGINT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (pet_id, tag_id)
);

-- store_orders
CREATE TABLE store_orders (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  pet_id      BIGINT NOT NULL REFERENCES pets(id) ON DELETE RESTRICT,
  quantity    INTEGER NOT NULL,
  ship_date   TIMESTAMPTZ,
  status      VARCHAR(16) NOT NULL CHECK (status IN ('placed', 'approved', 'delivered')),
  complete    BOOLEAN NOT NULL DEFAULT false,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- users
CREATE TABLE users (
  id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username     TEXT NOT NULL UNIQUE,
  first_name   TEXT,
  last_name    TEXT,
  email        TEXT,
  password     TEXT,
  phone        TEXT,
  user_status  INTEGER,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- shared updated_at trigger, attached to every table with an updated_at column
CREATE OR REPLACE FUNCTION set_updated_at() RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_categories_updated_at BEFORE UPDATE ON categories FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_tags_updated_at       BEFORE UPDATE ON tags       FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_pets_updated_at       BEFORE UPDATE ON pets       FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_store_orders_updated_at BEFORE UPDATE ON store_orders FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_users_updated_at      BEFORE UPDATE ON users      FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

## What later code can rely on

- Table/column names and types above are stable identifiers — `kysely-codegen` will generate a `Database` interface directly from this shape once the migration is applied (see `packages/api/CLAUDE.md`).
- `pet_photo_urls.position` is 0-based and contiguous per pet, matching the order of the contract's `photoUrls` array.
- Enum-like `status` columns are `CHECK`-constrained, not native Postgres enums — adding a new allowed value later is a single `ALTER TABLE ... DROP CONSTRAINT ... ADD CONSTRAINT ...` changeset.
- `store_orders.pet_id` deletion is `RESTRICT` — any future "delete pet" use case must handle the resulting DB error (e.g. surface a 409 Conflict) rather than assume the delete always succeeds.

## Out of scope for this contract

- Kysely repository code, NestJS DTOs, and controller wiring — a later feature.
- Password hashing/storage format for `users.password` — the column exists to satisfy the contract field; how the API populates it is an application-layer decision outside this schema feature.
